# Shioiri Archive

塩入友広のウェブサイトの原稿と、公開用 HTML を生成するプログラムです。

## フォルダ構成

```
content/
  posts/
    2026081401/        記事1件につきフォルダ1つ。名前は記事ID（後述）
      index.md         原稿（Markdown）。旧サイトから移した記事は index.html（後述）
      comments.yaml    旧サイトから転載したコメント（ある記事のみ）
      08a.png          この記事で使う画像・PDF など
  pages/
    top/index.md       トップページの上部に表示する内容
    profile/index.md   固定ページ（profile.html になる）。メニューに表示される
templates/             HTML の雛形（Jinja2）
static/                そのまま公開するファイル（CSS など）
  assets/images/       複数のページで共通して使う画像（人物写真など）
tools/
  import_wordpress.py  旧サイト（WordPress）からの取り込みプログラム（移行時に1回だけ使用）
config.yaml            サイト名・公開 URL・トップページの表示件数などの設定
build.py               生成プログラム
docs/                  生成された公開用ファイル（手元で確認するときだけ作る。リポジトリには入れない）
.github/workflows/     GitHub Actions の設定（push のたびにサイトを生成して公開する）
```

## 記事の書き方

1. `content/posts/` に、記事IDを名前にしたフォルダを作る。
   記事IDは「公開日8桁＋その日の連番2桁」。例：2026年8月14日の1本目は `2026081401`。
   **記事IDは公開日の唯一の根拠であり、URL（`2026081401.html`）にもなる。一度公開したら変更しない。**
2. フォルダの中に `index.md` を作り、先頭に設定（Front Matter）を書く。

```markdown
---
title: "記事のタイトル"          # 必須
caption: "タイトルの下に表示する一文"  # 任意。SNS 用の説明文にも使う
categories: "しおいり通信"       # 任意
tags: ["上田市", "議会"]         # 任意
updated: "2026-09-01"           # 任意。内容を修正した日
---

本文（Markdown）
```

`date` は書かなくてよい。書いた場合は、記事IDの日付と一致しなければエラーになる。

### 画像

画像ファイルを記事フォルダに入れ、本文にファイル名だけを書く。

| 書き方 | 表示 |
|---|---|
| `![説明文](photo.jpg)` | 中央に表示し、説明文をキャプションとして下に表示。クリックで拡大 |
| `![](photo.jpg)` | キャプションなし。続けて並べると間隔が詰まる |
| `[![説明文](photo.jpg)](https://...)` | クリックするとリンク先（PDF など）を開く |
| `![](photo.jpg){: .wide }` | 本文の幅いっぱいに表示 |

画像だけの段落が画像ブロックになる。文章の途中に書いた画像はそのまま表示される。

#### 共通の画像

人物写真やロゴなど、複数のページで使う画像は `static/assets/images/` に置き、
本文に `assets/images/` から始まる名前で書く。1か所を差し替えれば、使っているすべてのページに反映される。

```markdown
![](assets/images/portrait.jpg)      ← 共通の画像（static/assets/images/portrait.jpg）
![](photo.jpg)                       ← この記事のフォルダの画像
```

その記事だけで使う画像は、これまでどおり記事フォルダに置く（記事と画像をまとめて扱えるようにするため）。
共通の画像も、ファイルがなければビルドがエラーで停止する。固定ページの `image:`（SNS 用の画像）にも同じ書き方で指定できる。

### 非表示

Front Matter に `hidden: true` を書いた記事・固定ページは、サイトのどこにも出力しない
（記事ページ、トップページ、各一覧、検索、フィード、sitemap、前後の記事のリンク）。
非表示のページへのリンクが他の記事に残っている場合は、ビルドの最後に一覧を表示する。

**非表示は非公開ではない。** 原稿はリポジトリに残るため、リポジトリが公開されていれば GitHub 上で誰でも読める。
内容自体を公開しない場合は、原稿をリポジトリから除き、必要に応じて履歴からも削除すること。

### ランディングページ

選挙期間中の案内など、サイトの外から直接案内するためのページ。
`content/landing/<名前>/index.md` に置くと、`サイトのURL/<名前>/`（例 `https://shioiri.jp/26/`）として公開される。

- サイドメニューを持たない1カラムのページで、ホームページへのリンクと連絡先（`config.yaml` の `contact`）を表示する
- サイトの他のページ（メニュー、一覧、検索、フィード、sitemap）からはリンクしない
- 検索結果には出さない（noindex を指定している）
- 名前は英小文字・数字・ハイフン。他のページと重なる名前（例 `assets`）はエラーになる
- `hidden: true` で非表示にできる。画像は記事と同じく、同じフォルダに置いてファイル名で参照する

### 「続きを読む」

本文の段落の間に `<!--more-->` を1行で書くと、トップページではその前までを表示し、
「続きを読む」のリンクを付ける。記事ページでは全文を表示し、リンクは区切りの位置（`#more`）を指す。
区切りは1記事に1か所まで。段落の途中に書くとエラーになる。

### 固定ページ

`content/pages/` に、英小文字のフォルダ名（例 `profile`）でフォルダを作り、`index.md` を置く。
`フォルダ名.html` として公開され、メニューに表示される。
メニューでの並び順は Front Matter の `order`（整数。小さい順）で指定する。
`menu: false` と書いたページは、公開するがメニューには表示しない（他のページからリンクしてたどれるようにする）。

固定ページでは、検索結果や SNS での見え方を次の設定で指定できる（いずれも任意）。

| 設定 | 内容 | 書かない場合 |
|---|---|---|
| `head_title` | ブラウザのタブ・検索結果・SNS に表示するタイトル（そのまま使う） | 「title - config.yaml の title_suffix」 |
| `description` | 検索結果・SNS に表示する説明文 | caption、なければ本文の先頭（`description_length` 文字） |
| `image` | SNS で共有したときの画像。同じフォルダに置いたファイル名か、共通の画像（`assets/images/○○`）を書く（推奨 1200×630px） | 本文の最初の画像 |

## 旧サイト（smile.shioiri.jp）から移した記事

2026年11月、WordPress のエクスポートファイルから `tools/import_wordpress.py` で取り込んだ。

- 記事 8,433 件、固定ページ 3 件（about、recommend、guestbook）、コメント 1,795 件
- 本文は HTML のまま `index.html` として保存している。`build.py` は `index.html` の本文を変換せずに表示する。
  後日 Markdown に書き直す場合は、記事ごとに `index.html` を `index.md` に置き換えればよい（混在してよい）。
  ビルドのたびに、残っている `index.html` の件数が表示される。
- 投稿時刻を `time`、UTC との時差を `timezone`（例 `'-05:00'`）として Front Matter に記録している。
  時刻は投稿当時の現地時刻（英国・米国在住時の記事は現地の時刻）。日本時間以外の場合は画面に時差も表示する。
- 画像の多くは `https://ext.netlify.app/` に置いたまま参照している（GitHub への移動は未実施）。
- 元のエクスポートファイル（コメント投稿者のメールアドレス等を含む）はリポジトリに入れず、別に保管している。
- shioiri.wordpress.com（smile.shioiri.jp の前身）のエクスポートも照合済み。公開記事 262 件はすべて取り込み済みの記事と同一。
  下書き 5,537 件のうち、取り込み済みの記事にないものは 2020-04-09・2020-04-13 の2件だけで、これは個別に追加した。

### Google サイトから移した記事（マッチ箱）

2026年11月、Google サイト（sites.google.com/view/shioiri）の「マッチ箱」の Pack#001〜048（No.0001〜1090、写真 1,671 枚）を、
Google データエクスポート（Takeout）の HTML から `tools/import_matchbox.py` で取り込んだ。

- 1パックを1件の記事にした。記事IDの日付は、Google サイトの更新履歴に記録された各パックの公開日。カテゴリは「マッチ箱」
- 写真は長辺 800px に縮小した。説明文のハッシュタグは「#」を外して本文に残し、市町村名のものは記事のタグにした
- 品目ごとに見出し（`#no0001` の形の目印付き）を置き、元の X の投稿へのリンクを付けた。重複品は元の品目へリンクした
- 活動の説明とパックの一覧は、固定ページ `matchbox` に置いた
- Google サイトにある Pack#049 以降は写真がないため、取り込んでいない

### 取り込みを再実行しないこと

**取り込み後の記事は、`content/` 内の原稿を正本とする。**
取り込みプログラムを再実行すると、エクスポートファイルの内容で記事が作り直され、
取り込み後に `content/` 上で行った修正がすべて失われる。

取り込み後に行った修正：

| 日付 | 記事 | 内容 |
|---|---|---|
| 2026-11-11 | `2019111401` | タイトルを「今日のごはんと、台風の夜。」から「今日のごはん」に変更 |
| 2026-11-11 | `2019051701` | 重複していたコメント2件（番号 1830、1831）を `comments.yaml` から削除 |
| 2026-11-11 | `2019051701` | 時刻の記録がない（00:00:00）コメント2件（番号 1828、1829）の日時を日付だけに変更 |
| 2026-11-11 | `2026011301`→`2026011201`、`2026012801`→`2026011801`、`2026012802`→`2026012301`、`2026021701`→`2026021501` | しおいり通信（theLetter）からの転載記事の公開日を theLetter の日付に修正（記事IDを変更し、WordPress に転記した時刻 `time`・`timezone` を削除） |
| 2026-11-11 | `2026012803`→`2026012801` | 同日の他の記事の移動に伴い、連番を詰めた |
| 2026-11-11 | 2025-12-31〜2026-02-27 のしおいり通信の記事 18 件 | WordPress に転記した時刻（`time`・`timezone`）を削除し、theLetter のサブタイトルを `caption` に設定（本文先頭のサブタイトルの段落は削除） |

| 2026-11-11 | 固定ページ `about` | 内容をプロフィール（`profile`）に統合し、`hidden: true` に設定 |
| 2026-11-11 | 旧サイトの記事 296 件 | 取り込み時に除去した「続きを読む」の区切り（`<!--more-->`）を `tools/restore_more_markers.py` で復元 |

取り込み方法の変更等でやむを得ず再実行する場合は、事前にこの表と Git の履歴で修正内容を洗い出し、
再実行後に同じ修正を行うこと。修正を行った場合は、この表に追記する。

## 生成と確認

必要なもの：Python 3.9 以上、`pip install -r requirements.txt`

```sh
python3 build.py            # config.yaml の production の設定で生成
```

`docs/` が毎回作り直される。手元で確認するときは次を実行し、ブラウザで `http://localhost:8000` を開く。

```sh
cd docs && python3 -m http.server
```

原稿に誤り（存在しない画像、日付の不一致、未知の設定項目など）があると、
エラーメッセージを表示して停止し、`docs/` は変更されない。

## 公開

原稿をコミットして `main` ブランチに push すると、GitHub Actions（`.github/workflows/pages.yml`）が
GitHub のサーバー上で `python3 build.py` を実行し、生成結果を GitHub Pages に公開する。数分で反映される。
GitHub のサイト上で原稿を直して保存（コミット）した場合も同じ。

- GitHub Pages の設定（Settings → Pages）の「Source」は「GitHub Actions」にしておく。
- 生成結果（`docs/`）はリポジトリに入れない（`.gitignore` で除外している）。
  デザインを変えるたびに全ページ分の HTML が履歴に積み上がり、容量が増え続けるのを防ぐため。
- 原稿に誤りがあって生成がエラーで停止した場合は公開されず、公開中のサイトは前の状態のまま残る。
  結果はリポジトリの「Actions」タブで確認できる（失敗した場合は GitHub からメールでも通知される）。
- 「Actions」タブの「サイトを生成して公開する」→「Run workflow」で、手動でも生成・公開できる。
- **選挙期日の当日は push しないこと。** push すると自動で公開されるため、
  選挙運動用ウェブサイトの更新に当たる（公職選挙法第129条）。

## 生成されるページ

| URL | 内容 |
|---|---|
| `index.html` | トップページ（`pages/top` ＋ 最新記事のタイトル一覧 ＋ 最新記事の全文。件数は `config.yaml` の `top_list_entries`・`top_entries`） |
| `2026081401.html` | 記事 |
| `2026081401/画像` | 記事の画像 |
| `202608.html`（`202608-2.html` …） | 月別の記事。本文を10件ずつ表示（件数は `config.yaml` の `archive_entries`） |
| `2026.html` | 年別の記事一覧（タイトルと日付） |
| `profile.html` など | 固定ページ |
| `feed.xml` / `sitemap.xml` | 新着配信（Atom）／検索エンジン向けページ一覧 |
| `categories.html` / `tags.html` | カテゴリ・タグの一覧（記事数の多い順） |
| `category-○○.html` / `tag-○○.html` | 各カテゴリ・タグの記事一覧 |
| `search.html` / `search.json` | サイト内検索のページ／検索用データ（全記事のタイトルと本文）。検索は閲覧者のブラウザで `static/assets/js/search.js` が行い、外部の検索サービスは使わない |
